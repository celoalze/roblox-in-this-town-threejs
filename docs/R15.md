# R15 characters (Phase A core)

**R15 is the only character rig of the engine** (the legacy R6 rig was removed). This file is the rig contract (clothes/skin/face, hair/accessories/held props,
animations, links/IK/crowds). Owners: `engine/skeleton.js`, `engine/r15.js`, `assets/models/rigs/r15/`, `studio/export_r15.luau`, `studio/build_r15.py`, `docs/R15.md`, `stories/_r15test`,
plus `engine/character.js` (`buildCharacter`, `applyPose`: the facade over `r15.js`).

Every cast member is an R15 character (a `rig` key in a cast spec is ignored). Everything else (`pose()`, `registerAnims`, `setFace`,
`world.js` actor loop, expressions, blink, look-at) keeps working on R15 characters through the adapter. Test story: `stories/_r15test` (`python pipeline/produce.py _r15test --preview`; milo through idle, walk, run, wave, sit, jump...).

## 1. Files and functions

| file | what |
|---|---|
| `assets/models/rigs/r15/rig.json` | skeleton: `parts` (size, rest cframe, mesh file), `joints` (parent, child, c0, c1), `attachments`, hipHeight, height... **Roblox frame** (see 3) |
| `assets/models/rigs/r15/<Part>.json` | geometry of one part: `p` positions (xyz, studs, part-local, centred on the part origin), `uv`, `n` normals, `i` triangle indices. 15 files (14 body meshes + `Head`) |
| `engine/skeleton.js` | `SKELETONS = {r15: ...}`; `loadSkeleton(name)` (async, cached), `getSkeleton(name)`, `buildSkeleton(name, makeMaterial)`, `setJoint(sk, joint, [x,y,z])` |
| `engine/r15.js` | `buildR15(spec)`, `applyPose15(ch, pose)`, `legacyToR15(p, opts)`, `autoKnees(pose)`, `solveLeg`, `restPose()`, `REST`, `R15_JOINTS`, `R15_PARTS`, `rimify(material)`, `r15Ready` |
| `studio/export_r15.luau`, `studio/build_r15.py` | how the data was extracted / rebuilt (section 8) |

`r15.js` loads the rig data with a top-level `await fetch` when it is imported (via `character.js`), so `buildCharacter` stays synchronous. If the fetch fails only R15 is disabled (`r15Ready === false`, `buildR15` throws).

## 3. Coordinate conventions

* `rig.json` and the part jsons keep the **Roblox frame** (+Y up, front = -Z, character's right = +X). `skeleton.js` converts **once** to the engine frame by the half turn about Y
  (`p' = (-x, y, -z)`, `q' = (-qx, qy, -qz, qw)`, geometry and normals the same; winding is preserved). Engine: character front = **+Z**, feet on y = 0, the character's RIGHT side at **-X**
  (like the legacy rig: legacy `armL`/`legL`, at x = -1, are the character's **right** limbs = Roblox "Right Arm", the same fact `pipeline/rbx_anim.py` found).
* Joint rotation `[x, y, z]`: radians, three.js Euler `XYZ`, **relative to the rest pose** (zero = rest), expressed in the parent part's engine frame (all rest rotations are identity, so
  this is simply the parent's axes). Same handedness as the legacy rig: shoulder `x < 0` swings the arm forward, `z < 0` raises the character's right arm outward (`z > 0` the left arm), hip `x < 0` swings the leg
  forward, neck `x > 0` looks down (as legacy `hd`), knee `x > 0` and elbow `x < 0` flex.
* Grip attachment in the engine frame (arm hanging): local +X = engine +X, local +Y = forward (+Z), local +Z = down (towards the fingers). Hat/Hair attachments are at the top of the head, FaceFront on the front surface (+Z, at head height), all as plain Object3D children of the part.
* UVs are exactly what Roblox ships: each R15 mesh has its own 0..1 layout (not the classic 585x559 template: that mapping is applied by Roblox's clothing system per body part). Not flipped; check v orientation against a test texture before relying on it.
  UpperTorso front (Roblox -Z) spans u 0.01-0.33, v 0.29-0.61 of its own atlas; Head is the classic head mesh (its own UVs, front u 0.29-0.71, v 0.15-0.85).

## 4. The character object (`buildR15(spec)`)

| field | type | meaning |
|---|---|---|
| `rig` | `'r15'` | marks the character; `applyPose` routes on it |
| `root` | Group | feet on y = 0, front +Z; `root.scale = spec.scale`. The engine moves/yaws this |
| `body` | Group | child of root; `applyPose15` sets its y / lean / squash / forward offset (what legacy `body` did). Contains the whole skeleton |
| `hrp` | Object3D | HumanoidRootPart node, at height `rest.rootHeight` inside `body` |
| `joints` | `{name: Object3D}` | one pivot per Motor6D, keyed by Roblox name (`R15_JOINTS`). Pivot position = C0, rotation = the joint rotation (zero = rest). Use `getWorldPosition` for IK anchors |
| `parts` | `{name: Mesh}` | mesh of each part (`HumanoidRootPart` has none: its Object3D is returned) |
| `partNodes` | `{name: Object3D}` | the part's origin node; the child of its joint pivot; put things that must follow the part here (or use `attach`) |
| `attach` | `{name: Object3D}` | attachments by Roblox name, both `RightGripAttachment` and the short alias `RightGrip` (same object): `Hat Hair FaceFront FaceCenter Neck LeftCollar RightCollar BodyFront BodyBack WaistFront WaistBack WaistCenter LeftGrip RightGrip LeftShoulder RightShoulder LeftFoot RightFoot Root`. Positioned and oriented per the rig: add accessories / held props as children |
| `head` | Object3D | = `joints.Neck` (legacy `ch.head.rotation` still works) |
| `headSpace` | Group | child of the Head part node at the head centre (head mesh is centred on its origin): hats, hair, glasses as in legacy |
| `face` | Mesh | decal patch hugging the front of the head (raycast onto the head mesh at build time, offset 0.006, `polygonOffset`), planar uv with one atlas cell = 1.44 studs; `setFace` assigns `face.material.map` exactly as for R6 |
| `torso` | Object3D | = UpperTorso node (legacy `torso` was a hip pivot, see 7) |
| `armL armR legL legR` | Object3D | legacy aliases = joints `RightShoulder LeftShoulder RightHip LeftHip` (note the swap, see 3). Positions are in UpperTorso / LowerTorso space, NOT body space; `armL.userData.hand` = the grip attachment |
| `mats` | `{part: Material}` | own material instance per part (skin = MeshPhysicalMaterial like legacy, cloth/shoes as legacy, rim-light hook applied) |
| `setPartColor(part, '#hex')` | fn | recolours one part |
| `skin` | `{part: '#hex'}` | resolved colours (placeholder colouring: `skin`, `skinHead`, `skinTorso`, `skinArms`, `skinLegs`, `shirt`, `pants`, `shoes`, `jacket`, `sleeves` long/short/none, `bottom` pants/shorts/skirt, `partColors: {Part: '#hex'}`) |
| `spec`, `worn: []`, `hair: []` | | as legacy (`hair` empty: phase 2 fills it) |
| `rest` | object | copy of `REST`: `height hipY rootHeight thigh shank footH legLen shoulderY headCentreY` (engine units, unscaled) |

Shadows: every part mesh has `castShadow = receiveShadow = true`. Look: the rim-light shader hook of `engine/materials.js` (shared `RIM` uniforms) is applied through `rimify(material)` (exported from `r15.js`: use it for any new material).
Not done in Phase A: clothes textures, hair, hats, glasses, face extras (lashes/blush use the same atlas path), `details` (hood, pocket...), wear/held props, links (see section 7).

## 5. Pose format and API

```js
pose = { joints: { LeftElbow: [x,y,z], RightHip: [x,y,z], ... },   // any subset of R15_JOINTS, missing = rest
         y: 0,      // body height offset (engine units, up), as legacy
         lean: 0,   // radians about +X: positive = forward
         lh: 0,     // 1 = lean about the hips (pivot at rest.hipY) instead of the feet
         sq: 1,     // squash (<1) / stretch (>1), feet planted
         bz: 0 }    // forward offset (climbing)
applyPose15(ch, pose)                // writes every joint (missing ones reset to rest) + body fields. Call every frame.
applyPose(ch, p)                     // character.js: R15 characters accept either a pose with `joints` or a legacy pose (converted with legacyToR15)
legacyToR15(legacyPose, opts) -> pose
```

`legacyToR15` semantics (legacy pose `{la, ra, ll, rl, hd, ts, y, lean, sq, bz, lh}`):

* `la` -> RightShoulder, `ra` -> LeftShoulder, `ll` -> RightHip, `rl` -> LeftHip (legacy `la/ll` are the screen-left = character-right limbs); the angle triples pass through unchanged (same frame and handedness).
* Elbow: `opts.elbow` (default 0.2) x forward shoulder swing (clamped 0..1.6) flexes the elbow slightly; `0` = straight arms like R6.
* `hd` -> Neck; `ts` -> Waist (`opts.tsShare`, default 1). The R15 arms and head ride on the UpperTorso (in legacy the torso box twisted alone), so the neck cancels the waist rotation (`opts.headComp`, default 1): the head looks where the legacy head looked.
* `y`: negative `y` is scaled by `hipY/2` (R15 hips are 2.19 high, legacy 2.0; `opts.ySquat`), positive unchanged. `lean sq bz lh` pass through (hip pivot is `rest.hipY` instead of 2).
* `autoKnees(pose)` (`opts.knees = false` disables it), per leg, using the hip pitch (x) and the body height: (1) a thigh swung well forward (< -0.8 rad, sitting) lets the shank hang down; (2) if the sole would go through the floor
  (lowered body: sitfloor, swim, crouch, kneel) a 2-bone IK keeps the foot where the straight leg had it, bends the knee and swings the thigh a little further forward; (3) the ankle counter-rotates so the sole stays flat while the knee works.
  A straight, swinging leg (walk, run, jump) is untouched, so cycles match the legacy rig. `solveLeg(thighPitch, hipHeight)` is the pure function. Roll (z) of the hip is not considered.

Left out on purpose: finger/foot detail, wrist, per-joint ease. Native animations (phase 3) should write `pose.joints` directly.

## 6. How to add or change geometry

* Re-export: `studio/export_r15.luau` + `studio/build_r15.py` (section 8) regenerates `rig.json` and the part jsons. A part file is a plain `{p, uv, n, i}`; replace the file (same part-local frame, centred origin) to swap a mesh, keep the `rig.json` `size` in sync.
* New skeleton: add `SKELETONS.<name>` (url) and a `rig.json` of the same shape; `buildSkeleton(name, makeMaterial)` is rig-agnostic. `r15.js` is the R15-specific facade.
* Different head: the Head part is the classic Roblox head mesh (`rbxasset://avatar/heads/head.mesh`) fitted to the R15 head size; the face patch is raycast onto whatever `Head.json` contains.

## 7. What each later phase may touch / must know (historical: phases 1-4 are done; the notes show what each part of the engine owns)

Phase 1 clothes/skin/face: own `ch.mats` / `setPartColor` and `partColors()` placeholder in `r15.js` (replace it: part-wise textures through the R15 UVs; `face` plane and `setFace` stay as they are; `faceGeometry()` is the place to change the face fit).
Phase 2 hair/accessories/held props: attach to `ch.attach.*` / `ch.headSpace` / `ch.partNodes.*`; fill `ch.hair`; legacy `holdProp` (world.js) uses `armL/armR.userData.hand` and `armTip`, which assumes the R6 arm block: re-base it on `attach.RightGrip` / `LeftGrip` (note: Grip +Z points down the fingers in the engine frame). `rimify` is exported.
Phase 3 animations: write `pose.joints` (R15-native keys) and a migration of the legacy 6-joint anims: `legacyToR15` is the reference adapter. `config/anims*.json` stays legacy until then. The retarget conventions are in `pipeline/rbx_anim.py`; R15 KeyframeSequence poses map to `joints` rotations with the Q-conjugation derived there (C0/C1 rotations are identity in R15, so the pose rotation is the joint rotation in the parent frame, then conjugate with D = diag(-1,1,-1)).
Phase 4 links/IK/crowds: `armToward`, `shoulderW` and `tp()` in `links.js` use `ch.armL.position` / `ch.torso` as R6 body-space frames: `joints.*` positions are relative to their parent part, and `ch.torso` is the UpperTorso node (legacy `torso` was a pivot at the hips with +y up to the shoulders at 1.5-2, scale 2 per box). Use `getWorldPosition` of `joints.RightShoulder` etc. and `rest.*` for dimensions. Arm length shoulder->wrist = 1.58, wrist->fingertips ~0.29, 1.87 total (R6: 2.0).
Files NOT to edit from phases: `skeleton.js` (extend through new exported functions only), the rig data (re-export instead).

## 8. How the data was extracted (Roblox Studio MCP)

1. `list_roblox_studios`, then `execute_luau` (datamodel Edit) with `studio/export_r15.luau`: `Players:CreateHumanoidModelFromDescription(Instance.new("HumanoidDescription"), Enum.HumanoidRigType.R15)` (note: `HumanoidDescription.new()` does not exist, use `Instance.new`).
2. Geometry: `AssetService:CreateEditableMeshFromPartAsync` does not exist in this build, but **`AssetService:CreateEditableMeshAsync(Content.fromUri(meshPart.MeshId))` works** for the 14 body MeshParts (exact vertices, normals, uvs, triangles; vertices are in the mesh's 1-stud-normalised space and are scaled by `Size / MeshSize`; ~170-500 verts per part). The new dynamic Head asset (id 123480233606534) and the classic head asset ids are NOT loadable ("no permission to load asset"), but the built-in `rbxasset://avatar/heads/head.mesh` is: its bounding box is fitted to the Head part size. (Option (b), assetdelivery via `pipeline/rbxmesh.py`, was not needed.)
3. Skeleton: the model uses AnimationConstraints named Root/Waist/Neck/...; C0 = Attachment0.CFrame, C1 = Attachment1.CFrame. Part rest CFrames are taken relative to HumanoidRootPart. Everything is encoded as integers (positions x1e4, rotation matrices x1e5, uv x1e4, normals x1e3).
4. Result transport: the tool truncates a returned string at ~100 KB (the full file is 240 KB), so the JSON is stored as StringValues (max 200000 chars each, 90000 used) in `ServerStorage.R15Export` and fetched with three `return ...Value` calls; the tool saves each oversized result to a file under `.claude/projects/.../tool-results/`, which a python script concatenates into `cache/r15/raw.json` (never printed). `ServerStorage.R15Export` and `Workspace.R15Probe` are destroyed afterwards.
5. `python studio/build_r15.py` -> `assets/models/rigs/r15/` (checks that every child's rest CFrame equals `parent * C0 * C1^-1`).

## 9. Known gaps / weak points

* No hair, hats, glasses, clothes textures, hoodie details or held props on R15 yet (flat colours only); the face has no lashes/blush extras beyond the atlas path.
* Head: classic head mesh (not the dynamic Roblox head), slightly smaller than the legacy head (R15 head 1.16 wide vs 1.28): faces read a little smaller.
* `sit`: R6 sits with straight horizontal legs, R15 hangs the shanks (knees bent): not identical on purpose (better on a chair, the seat height of existing sets was tuned for R6).
* Legacy IK (`links.js`, `holdProp`, crowd code) is not R15-aware; do not use props with `hand` or `link:` on R15 characters before phases 2 and 4.
* Elbow/knee are driven only by the adapter; shoulder pivot differs from R6 so raised arms are a bit narrower (cheer, jump) than the legacy block arms.
* Hip roll is ignored by the leg floor solver; `lean` is applied to the whole body about the feet (or the hips with `lh`) exactly like legacy.

## 10. Attachments, hair, accessories, held props (Phase B2)

Owner: `engine/r15_attach.js` (new), plus `wear.js` (`partSpace`), `layers.js` (`layerHair` space), `headgear.js` (`buildHeadgear`), the `holdProp` branch in `world.js`, `stories/_r15attach`.

* **Head gear space `ch.fitSpace`** (child of `ch.headSpace`): all hair data (Roblox meshes, strand hair, hair colours), hats (procedural `hat:`, Roblox `wear`/`+cap`, GLB `+crown` etc.), glasses and face-slot accessories were authored for the R6 head (2*0.64 wide, 1.24 tall, centred). `fitSpace` is scaled per axis and centred so that box maps onto the bounding box of the R15 Head mesh (currently x/z 0.905, y 0.953). Anything R6-authored put inside sits on R15 as it sat on R6; hair-under-hat layering (`layers.js`) works in that space unchanged. `refitHead(ch)` recomputes it: call it if the Head mesh is rescaled after build (a scale on the Head part node propagates by itself). Use `partSpace(ch, 'head')` (never `headSpace`) to parent head gear; `ch.hair` holds the hair roots.
* **Torso accessories** (`slot` of config/wearables.json: neck, back, front, waist...) hang from the real attachment of the slot (`SLOT_ATT`: neck -> NeckAttachment, back -> BodyBackAttachment, front -> BodyFront, waist -> WaistCenter, `shoulderL/R` -> Left/RightCollar; optional `"att": "<name>"` per item overrides). The data is stored relative to the R6 torso centre with the R6 attachment baked in, so the group sits at the R15 attachment and the data origin is moved back by the R6 attachment point (`R6_ATT`). Head slots hat/hair/face use fitSpace (R6 Hat/Hair/FaceFront mapped by the fit scale: hat point ends 0.018 below the Roblox R15 HatAttachment, i.e. the same relative height as on R6).
* **Held props**: `holdProp` (world.js) calls `carryHands15(ch, two, left, inward)` for R15: carry pose on shoulder + elbow (`carryArm15`: only hanging / swinging arms change), then tip = world position of the Right/LeftGripAttachment (hand end), dir = grip +Z (down the fingers). The rest of the logic (prop upright, pushed past the tip plane, GRIP `grip` / `hs` / `yaw` / `tilt`) is shared. Two-hand carries (GRIP `two`) use both arms, optional `inward` (shoulder roll, default 0.3) in GRIP. Exports for IK code (links): `gripFrame15(ch, armOrJointName) -> {pos, dir}`, `carryArm15`, `carryHands15`; they only write shoulder/elbow rotations (after `applyPose`, reset by the next one).
* Test: `python pipeline/produce.py _r15attach --preview`.
* Weak spots: the prop is placed beyond the hand end, not wrapped by the fingers (as on R6); carry angles were tuned by eye (single hand: shoulder -0.3, elbow -1.0; two hands: -0.4 / -0.8). `shoulderL/R` and `waist` slots are mapped but no item uses them yet.

## 10. Skin, clothes, face (Phase B1, `engine/r15_skin.js`)

`buildR15` calls `buildSkin(ch, spec)` (one line, before `attachGear`). It replaces the placeholder materials of `ch.mats` in place, fills `ch.skin`, fits the face and adds the procedural details. Test story: `stories/_r15skin` (R15 line-up, classic clothes, template, close-ups, back, side). `config/roblox_clothes.json` has a test entry `_tpl` (shirt + pants, labelled template `assets/roblox/clothes/s__tpl.png` / `p__tpl.png`: coloured regions, per-face labels, 1/8 height ticks): use `"shirt": "rbx:_tpl"` to check a mapping.

* **Colours** (same spec keys as R6): `skin`, `skinHead/Torso/Arms/Legs`, `shirt`, `pants`, `shoes` (default pants x .45), `jacket` (arm colour), `sleeves` long/short/none, `bottom` pants/shorts/skirt, `hands` (R6 rule kept: long sleeves cover the hands, skin hands only with `hands: true` or short/none sleeves), `partColors: {Part: '#hex'}`. Feet = shoe colour (R6 shoe). Short sleeves split the UpperArm at 38% of the arm, shorts split the UpperLeg at 42% of the leg, by a 1-D strip texture (same cut heights as R6). Skin = MeshPhysicalMaterial, cloth = fabric normal map, as R6.
* **Classic templates (`rbx:<name>`)**: no UV data was changed. For each part a non-indexed copy of the geometry is built at runtime (`remapGeometry`, cached): each triangle takes the dominant axis of its normal (front/back/left/right/top/bottom), picks that face's region of the 585x559 template (tables `T_TORSO`, `T_RIGHT`, `T_LEFT` in `r15_skin.js`), and the position inside the region is a planar projection of the vertex position in the rest pose. Groups: torso = UpperTorso+LowerTorso (one 2 x 2.1 stud box), each arm = UpperArm+LowerArm+Hand, each leg = UpperLeg+LowerLeg+Foot (hip joint to sole, so sneakers painted at the bottom of the pants land on the feet). Verified against the labelled template: orientation and left/right match R6 on every face. Layers as R6: skin < pants < shirt; plain shirt colour + rbx pants gives a plain torso (as R6). One 585x559 canvas per group (torso/arms/legs), repainted when the PNG arrives (own loader, independent of `preloadClothes`).
* **Details** ported from R6 onto UpperTorso / LowerTorso (R6 torso space 0..2 mapped by a scaled group): crewneck, collar, buttons, tie, badge, belt, pocket, kangaroo, hood (collar block + strings), stripes, heart/star, jacket (side slabs), logo plane, cuffs (LowerArm), skirt (cone) / shorts band. Not ported: hands: true skin box beyond the colour rule. Details are skipped for `rbx` shirts (as R6). They follow the waist twist only on the part they sit on.
* **Face**: same `ch.face` patch (`setFace`, expressions, gaze, brows, tears, lashes, blush unchanged). The Head node is scaled by `HEAD_SCALE = 1.1` about the neck pivot (all children, hats, hair, `headSpace` follow); face atlas span 1.41 studs. Total height grows by ~0.12 stud. Looks like R6 in close-ups and reads at phone size.
* **Rim shader**: `rimify` (same `RIM` uniforms) on every material, shadows on all meshes.
* Weak spots: `setPartColor` on a textured part tints the texture (multiplies); template mapping stretches the 2.1-stud torso / 2.19-stud legs 5-10% over the R6 2.0; bevel triangles are projected onto one face (tiny smear); skirt and hood are approximations; no T-shirt graphics (R6 has none either, only `logo`).

## 10. IK, links, look-at, crowds (Phase B4)

* **IK API (`engine/links.js`)**: `armToward(ch, 'L'|'R', worldTarget, k = 1, lim = [.6, 1.3], o = {})` (side = legacy alias: `'L'` = `ch.armL` = Roblox RightShoulder, `'R'` = LeftShoulder). On R15 it is a real 2-bone solve
  (shoulder gets a full rotation, elbow one hinge angle, segment lengths read from the skeleton, hand centre reaches the point): `o.tip` `'hand'` (default) | `'wrist'` | `'grip'`, `o.hint` (elbow direction in the UpperTorso frame, default out/down/back) or `o.hintW` (world),
  `k` blends from the pose already on the joints. Out of reach the arm straightens and stretches up to `lim[1]` (shoulder pivot `scale.y`, reset by `resetIK(s)` each frame; `o.stretch === false` = clamp only). 
  `footTo(ch, 'L'|'R', worldTarget, k, o)` = same for legs (hip-knee-ankle, knee hint forward, `o.flat` levels the sole; R15 only). `headY(ch)` = head centre height (R15 4.87; creature models without R15 data use 4.6).
* **Links on R15**: `MODES` in links.js (the only mode table). Hip frame of `tp()` = Waist pivot minus 0.4; child pivot uses `rest.hipY`. Poses are still the legacy `anims_interact.json` data through `legacyToR15`; arms are replaced by IK; `ov(who, s, r)` in a mode returns joint overrides laid over the pose (hook exists, unused so far).
  `reach:` uses the same solver. Hugs wrap real arms, hold_hands joins hands (both hands at one point), carry cradles with bent elbows.
* **Look-at / camera / lint**: world.js `headPos`, the shot look point, the look-at pitch and `lint()` read `headY(ch)`; `engine/face2.js` (gaze) reads the character's `rest.headCentreY` (4.87). Look-at turns go through legacy `hd`/`ts` -> Neck + Waist (`legacyToR15`).
* **Crowds / extras**: `buildExtras` builds R15 NPCs; materials are shared by colour (`shareMats`). Crowd behaviours animate through legacy poses -> `applyPose`. The `mob` prop (props.js) is instanced blocks with R15 proportions.
* Test story: `stories/_r15links`. Weak spots: piggyback kid legs are the adapter's (autoKnees) hang, not hooked; carry cradle is a bit stiff; hugs at equal size are tight.

## 10. Native R15 animation (Phase B3)

Files: `engine/anim15.js` (sampler, blending, bridge), small edits in `engine/character.js` (`registerAnims`, `pose`, `blendPose`, `blendPoseLag`, `applyPose`), `config/anims_r15.json` (115 Roblox clips, native),
`config/anims_r15_hand.json` (12 acting anims, `pipeline/r15_hand.py`), converter `pipeline/rbx_anim.py` (`native`), check story `stories/_r15anim` (`gen.py`).

**Format** (entry in any `config/anims*.json`): `{"rig": "r15", "loop": s|0, "held": bool, "hip": bool, "keys": [{"t", "joints": {"LeftElbow": [x,y,z], ...}, "y", "lean", "sq", "bz", "ease"}]}`.
Euler XYZ radians relative to rest, engine frame (section 3), joints omitted = rest; `ease` = how the pose ARRIVES at the key (smooth default, linear, back, spring); `loop`, `held`, `hip` as legacy (hip: `lean`/`bz` pivot at the hips).
Between keys each joint is a quaternion slerp (shortest path, so angles beyond 2pi never spin; a rotation over 180 degrees needs an intermediate key; `lean`, `y`, `bz`, `sq` are plain scalars and may exceed 2pi, but end an anim at lean 0: duplicate-time keys are allowed, see `tumble`).

**Naming rule.** A native entry has the plain anim name (`rig: "r15"` marks it; the old `@r15` suffix is gone). A legacy-format entry of the same name in another config file would be overridden.
`registerAnims` stores `NATIVE[<name>]`; `pose(name)` returns the legacy-format fields plus `p.n` (native pose); `applyPose` uses `p.n`. The legacy fields every consumer such as links / crowds still reads are derived from the native keys (`toLegacyKey`).
The legacy twins of the native entries (config/anims_roblox.json and 12 in anims_hand.json) were deleted in the R6 removal (backup: cache/backup_anims_20261113).
Every other anim (procedural `pose()` cases, legacy JSON) reaches R15 through `legacyToR15` as before; so all names play on R15.

**Blending.** `blendPose` / `blendPoseLag` blend `p.n` too (joint slerp; a legacy-only side is converted with the adapter), so crossfades between any two anims work. The engine tweaks legacy fields after `pose()` (acceleration lean, head drag, landing squash, held breathing): `p.n.b` is the snapshot of the legacy fields at creation and `nativeToPose` adds `(p - b)` onto the native joints/lean/y/sq. Layers (`walk+wave`): base keeps Root, Waist, legs; the second gives the arm joints (shoulder, elbow, wrist, both sides) and its Neck is added.

**Native conversion** (`rbx_anim.py native <name> <assetId>`, from `cache/rbx_anim`): R15 poses are Motor6D transforms with identity C0/C1 rotations, so joint = D R D (D = half turn about Y), nothing retargeted. R6 clips map their 6 poses onto Shoulder/Hip/Neck (Q conjugation, QS / QL / QR in rbx_anim.py), no elbows/knees. Body: Root = R_HRP * R_LowerTorso (pivot = hip, like Roblox);
the HRP rotation pivots 1.0 above that, so the pivot translation `p_hrp + (R_HRP - I)c + R_HRP p_LT` (c = (0,-1,0)) becomes `y` and `bz` (= -Z). X translation is dropped. Time scale, ground contact (`ground`: per key the lowest sole point goes to the floor, by FK) and lean add-on come from the options of the command. `_sources` of anims_r15.json records them.
